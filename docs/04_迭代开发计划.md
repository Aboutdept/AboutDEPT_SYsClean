# SysClean 迭代开发计划

> 目的：基于 `01/02/03` 三份分析，给出"先分析→再规划→最后执行"的落地计划。
> 每个迭代写明：**目标 / 调整内容（改哪些文件、加什么） / 验证方法 / 风险**。
> 总原则：只删明确垃圾、不做注册表优化/SSD 安全擦除、精确删除+排除保护、关键操作用户确认、保留中文与 VP 垂直深度。

---

## 路线图总览

| 迭代 | 主题 | 解决差距 | 改动规模 | 风险 |
|------|------|----------|----------|------|
| **迭代 1** | 地基：相关性 + 可扩展性 + 持久化 | G1 安装检测 / G3 自定义规则 / G5 设置 / G11 路径展开 | 中 | 低 |
| **迭代 2** | 覆盖广度：winapp2 数据库 + 全局排除 | G2 覆盖 / G6 排除 | 中 | 中 |

## 迭代 1：地基 —— 安装检测 + 自定义规则 + 设置持久化 + 路径展开

**目标**：让扫描"只显示已安装 App"、让用户能加自己的规则、记住用户选择、统一路径表达。

### 调整内容

1. **`scanner.py` — `ScanItem` 增加字段**
   ```python
   detect: list = field(default_factory=list)   # 例: ["%LocalAppData%\\UnrealEngine",
                                                 #       r"HKLM\Software\Epic Games"]
   detect_reg: list = field(default_factory=list)
   custom: bool = False                           # 来自 Custom/ 的为 True
   source: str = "builtin"                        # builtin / winapp2 / custom
   ```
2. **新增 `scanner.py` — `PathExpander` 类**
   - `expand(path)`：展开 `%LocalAppData% %AppData% %ProgramData% %ProgramFiles% %ProgramFiles(x86)% %UserProfile% %SystemRoot% %Temp% %Documents% %Videos%` 等（用 `os.environ` / `shell:knownfolder` 映射）。
   - `resolve_wildcards(path)`：对含 `*` 的段递归展开为真实路径（参考 FluentCleaner `PathExpander.ResolveRecursive`）。
   - `get_scan_targets()` 与 `winapp2_parser` 统一调用它。
3. **新增 `scanner.py` — `DetectionService`**
   - `is_installed(item)`：遍历 `detect`（文件/文件夹存在即 True）与 `detect_reg`（注册表键存在即 True），OR 逻辑。
   - 在 `scan_all()` 中：未安装项不打分、可配置为"隐藏"或"灰色折叠显示"。
4. **新增 `Custom/` 目录 + `load_custom_rules()`**
   - 读取 `Custom/*.ini`，语法采用 winapp2 子集：
     ```
     [My Tool Cache]
     DetectFile=%LocalAppData%\MyTool
     FileKey1=%LocalAppData%\MyTool\Cache|*.tmp;*.cache|RECURSE
     ```
   - 解析后转成 `ScanItem`（复用迭代 2 的解析器，迭代 1 可先做极简版：仅 `DetectFile` + `FileKey1`）。
   - 支持 `.disabled` 后缀停用。
5. **新增 `settings.py` — `AppSettings`**
   - 持久化：`selected_ids`（上次勾选）、`window_size`、`enabled_databases`、`global_exclusions`。
   - 存储：`settings.json`（exe/脚本旁即便携模式；否则 `%AppData%/SysClean/settings.json`）。
   - GUI 启动时加载 `selected_ids` 并预选。

### 验证
- 没装 Unreal Engine 的机器：UE 相关项不再污染结果（隐藏或折叠）。
- 在 `Custom/` 放一个测试 ini → 扫描列表出现该条目且能正确统计大小。
- 勾选若干项、关闭重开 → 选择被记住。
- 路径含 `%LocalAppData%` 的规则被正确展开。

### 风险
- 低。纯新增，不改现有 80 条逻辑；旧行为通过"detect 为空视为已安装"兼容。

## 迭代 2：覆盖广度 —— winapp2 解析器 + 加载器 + 全局排除

**目标**：把社区 3721 条规则（及用户自定义）纳入，覆盖数千款通用 App；用 ExcludeKey 防误删。

### 调整内容

1. **新增 `winapp2_parser.py`**
   - 解析 `[Name]` / `LangSecRef` / `Detect` / `DetectFile` / `FileKeyN`（路径|模式|RECURSE|REMOVESELF）/ `RegKeyN` / `ExcludeKeyN` / `Warning` / `Default`。
   - 输出 `CleanerEntry`（与 `ScanItem` 互转）。
2. **`scanner.py` — `get_scan_targets()` 合并三源**
   - `builtin`（现有 80 条）+ `winapp2`（随包或用户指定）+ `custom`（迭代1）。
   - 按 `LangSecRef`/分类排序；同名去重（builtin 优先）。
3. **`AppSettings` 增加**
   - `enable_winapp2`、`winapp2_path`、`global_exclusions: list`。
4. **`CleanEngine` 增加排除处理**
   - 清理前比对 `ExcludeKey`（FILE 精确名 / PATH 整树 / 通配），命中则跳过。
   - 全局排除列表优先于一切。
5. **可选**：随包附带一份**精简版** `Winapp2.ini`（去除明显危险的注册表项，只保留文件清理），或仅在设置里指向用户自己下载的完整版。

### 验证
- 加载 winapp2 → 条目数从 80 涨到数千（已安装 App 经检测后只显示相关子集）。
- 配置一条 `ExcludeKey` 保护某 `.db` → 清理时该文件被跳过并有日志。
- 关闭 `enable_winapp2` → 回到仅内置条目。

### 风险
- 中。winapp2 含注册表规则；SysClean **默认只执行 FileKey，忽略 RegKey**（对齐"不做注册表优化"哲学），避免误改注册表。需在解析时显式丢弃 RegKey 或仅作只读提示。

## 迭代 3：自动化 —— CLI 模式 + 清理日志文件

**目标**：支持计划任务静默清理；每次清理留审计日志。

### 调整内容

1. **新增 `cli.py`**
   - 参数：`--scan`（仅扫描出报告）、`--clean`（清理，可 `--category <名>` / `--all` / `--selected`）、`--auto`（用 settings 里保存的选择静默清理）、`--report <path>`（导出 JSON/CSV/TXT）、`--export-log`。
   - 例：`python main.py --auto --report cleanup_2026-07-12.json`
2. **`main.py` 增加参数解析**：有 CLI 参数时走 `cli.py`，无则正常起 GUI。
3. **`CleanEngine` 写日志文件**
   - 每轮追加到 `SysClean_cleanup.log`（或 `%AppData%/SysClean/auto.log`）：时间戳 + 每条删除路径 + 释放大小 + 总计。
   - 与现有应用内日志并行，不冲突。
4. **文档**：在 README 增加"任务计划程序"配置示例（指向 `python main.py --auto`）。

### 验证
- 命令行 `--scan --report x.json` 生成报告且 GUI 不弹窗。
- `--auto` 用保存的选择清理，并生成 `auto.log`。
- 日志内容与实际删除一一对应。

### 风险
- 低。CLI 是新增入口，不影响 GUI。

## 迭代 4：空间分析 Tab（WizTree 启发）

**目标**：弥补"只扫预定义路径"的盲区，直接找 VP 项目里的空间杀手。

### 调整内容

1. **新增 `analyzer.py`**
   - `scan_tree(root)`：递归统计各子文件夹大小（带**目录/文件数上限**与**超时保护**，避免卡死）。
   - `top_large(n)`：返回最大的 n 个文件夹/文件。
   - `by_type()`：按扩展名归类的空间分布（视频/缓存/工程文件…）。
   - 可选：尝试读 NTFS MFT 提速（进阶，先不做；先用 `os.scandir` 足够）。
2. **`gui.py` 新增"空间分析"页（Notebook 或新 Frame）**
   - 选择根目录（默认 `C:\Users\<me>` 或某工程盘）→ 显示 Top 大文件夹列表 + 类型饼图（用 tkinter Canvas 画简单饼/条）。
   - 支持"仅显示可清理类型"（缓存/临时/预览）。
   - 右键"加入自定义规则" → 一键生成 `Custom/*.ini` 草稿。
   - 导出 CSV。
3. **与现有扫描联动**：空间分析发现的某大缓存文件夹，可"发送到清理"（转为临时 ScanItem）。

### 验证
- 选一个含大文件的目录 → Top 列表正确、大小求和等于该目录。
- 类型分布饼图比例正确。
- CSV 可在 Excel 打开。

### 风险
- 低。独立模块；扫描加保护避免遍历符号链接/超深目录卡死。

## 迭代 5：系统修复 + 精准 Installer 清理（Dism++ / PatchCleaner 启发）

**目标**：把"只读说明"升级为"受控可执行操作"，且不破坏系统。

### 调整内容

1. **新增 `repair.py`**
   - 封装（均带确认 + 管理员检测）：
     - `sfc_scan()` → `sfc /scannow`
     - `dism_restore()` → `DISM /Online /Cleanup-Image /RestoreHealth`
     - `dism_component_cleanup()` → `DISM /Online /Cleanup-Image /StartComponentCleanup`（真正安全清理 WinSxS）
     - `disable_hibernate()` → `powercfg /h off`（释放 hiberfil.sys）
2. **`gui.py` — 只读项升级为"操作按钮"**
   - WinSxS 项：显示"运行组件清理"按钮（调 `dism_component_cleanup`），不再只是文字。
   - hiberfil 项：显示"关闭休眠释放空间"按钮。
   - 这两项保持"需确认 + 需管理员"，不自动执行。
3. **Installer 孤立项识别（PatchCleaner 思路）**
   - 扫描 `C:\Windows\Installer` 与 `$PatchCache$`，比对"被已装产品引用"的 .msi（用 `MsiEnumProducts` / 注册表 `HKLM\Software\Microsoft\Windows\CurrentVersion\Installer\UserData`）。
   - **只把未引用的孤立项**作为可清理 ScanItem 呈现（非整目录只读）。
   - 此功能标记为 `caution` + 二次确认。

### 验证
- 点"运行组件清理"→ 弹出 UAC/管理员提示 → 调用 DISM 并回显输出。
- Installer 扫描：被引用的 .msi 不出现，孤立项出现并可清理。
- 不破坏任何已装程序的修复/卸载能力（关键回归测试）。

### 风险
- 中。涉及系统命令；必须：① 仅用户主动点击触发 ② 管理员权限检查 ③ 明确警告 ④ 不自动执行。
